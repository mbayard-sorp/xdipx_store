# CI flake / endemic-failure register

One row per check that fails for reasons unrelated to the PR that trips it —
endemic (fails on main / across unrelated branches) or genuinely flaky
(non-deterministic, passes on a bare re-run). Diagnosed once here, then
cited rather than re-investigated on every PR that hits it. Maintained by
R-SHEP (`.claude/agents/pr-shepherd.md`); see its `<flake_register>` section
for the process.

| `migration-dry-run` | 2026-08-20 (PR #791); recurred 2026-08-22 (PR #838) | Fails on every PR touching `db/migrations/**`, not just PRs that introduce a bug. `db/migrations/0002_fluffy_james_howlett.sql` ('auto'-classified) creates an index on `order_line_items`, a table only `db/migrations/009_copurchase.sql` ('manual'-classified) creates. `runDryRunMode` (scripts/apply-additive-migrations.ts) correctly skips 'manual' files (mirrors production safety — an owner must run those by hand), but a scratch CI database starts empty, so skipping 009 strands `order_line_items` and 0002 fails with `relation "order_line_items" does not exist` before the PR's own migration file is ever reached. This is a structural gap in the check's design, not a defect in any specific PR's SQL: it reproduces identically on `main` (no migration PR needed — a scratch DB replay of the current `db/migrations/` directory fails the same way) and will keep failing on every future migration PR until resolved. | `0002_fluffy_james_howlett.sql`, `009_copurchase.sql`, `0001_social_posts.sql`, and `005_deal_flow_reengineer.sql` are all already on `origin/main` (confirmed via `git show origin/main:db/migrations/<file>`), i.e. none of this is introduced by PR #791 — the inconsistency predates the check. Reproduced locally against a real `postgres:16` server (not the CI container) with `DATABASE_URL=postgresql://ci:ci@localhost/ci npx tsx scripts/apply-additive-migrations.ts --dry-run` on this branch: fails at `0002` with `relation "order_line_items" does not exist` every time, before this PR's own diff (`.github/workflows/ci.yml` only) is ever reached.
